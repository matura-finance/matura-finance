This is the shape of the live demo. The authoritative, step-exact script is
[`docs/demo-script.md`](https://github.com/matura-finance/matura-finance/blob/main/docs/demo-script.md)
in the repo, with a pre-flight checklist in
[`docs/demo-operator-checklist.md`](https://github.com/matura-finance/matura-finance/blob/main/docs/demo-operator-checklist.md).

## Before the demo

- A wallet funded with test BNB from the [faucet](https://www.bnbchain.org/en/testnet-faucet) (gas for
  `executeRoute`).
- The readiness gate green — a read-only pre-demo check confirms a request claims `ELIGIBLE`, per-leg
  vault liquidity is sufficient, and the operator has gas. (`smoke:bsc-testnet` / `smoke:local`.)
- Contracts verified and seeded (see [Deployed addresses](/docs/contracts/deployed-addresses)).

## The flow (≤3 min)

1. **Connect & sign in.** Open [`app.usematura.xyz`](https://app.usematura.xyz), connect the wallet on
   chain `97`, sign in with SIWE.
2. **Create a claim.** Use `/issuer` (the demo simulator) to produce an EIP-712 attestation and
   register a claim.
3. **Optimize.** On `/request`, run the best-execution optimizer — show the cheapest route across the
   competing vaults, with the per-leg breakdown and total received.
4. **Sign & submit.** Review → sign the EIP-712 `ExecutionRoute` → submit `executeRoute`. The router
   re-validates on-chain before funds move.
5. **Prove it.** `/activity` shows the execution with a BscScan link; `/account` reflects the new
   state once indexed.
6. **Settle (optional).** Drive settlement to show the conservation-checked waterfall repay the vaults
   (`demo:settle` locally for the full e2e).

## If something's off

Most demo failures are environment issues (wrong `SIWE_DOMAIN`/CORS, unfunded operator, post-write
index lag). The operator checklist enumerates abort conditions; don't start with any open.
